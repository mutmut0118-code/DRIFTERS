# Paper Towns (towns and roads in the far view) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Go given** by the user on 2026-11-14. Task 0 (the spike) is done: findings in
> `docs/superpowers/specs/2026-11-14-lod-towns-spike-findings.md`. Tasks 5 to 7 below were rewritten from them at the
> gate; Part 2 starts when the user has looked at the result.

**Goal:** With Distant Horizons or Meridian on, every place and road of the world plan, lit at night, shows in the far
view at its real spot before it's really built; up close the real town takes over without a visible jump.

**Architecture:** A rough sketch of every place (shape, streets, house boxes, fields, lamps) is made in the background
right after the plan, from the generator's heights, and saved with it. One painter (`FarPaint`) turns sketches and
unbuilt road stretches into per-column answers (surface block, raised spans, light); a Distant Horizons hookup and a
Meridian hookup each ask it. The real `TownBuilder` lays its streets with the same code, shape, headings and seed as the
sketch, so the real town comes out in the same shape. Clients get the sketches by packet. A throwaway spike first
settles how each LOD mod is hooked.

**Tech Stack:** Fabric 1.21.1, Mojang names, addon source sets `src/civ` (common) and `src/civClient`; Distant Horizons
3.3.3 API (`com.seibel.distanthorizons.api`), Meridian 0.3.0 API (`com.leclowndu93150.meridian.api`), both optional.

**Spec:** `docs/superpowers/specs/2026-11-14-lod-towns-design.md` (read it in full first; this plan argues from it).

## Global Constraints

- Addon only (`src/civ`, `src/civClient`), Drifter reached only through `com.dinglebob.drifter.api`. Client-only code in
  `src/civClient`; common code never imports `net.minecraft.client.*`.
- Distant Horizons, DH SeedGen, Meridian: optional, detected at runtime, no entry in any `fabric.mod.json` `depends`.
  Every class that names one of their types is loaded only after `FabricLoader.isModLoaded(...)` says yes, inside a
  `try`/`catch (LinkageError | RuntimeException)` that logs once and switches that hookup off.
- Meridian and SeedGen are All Rights Reserved: their jars never enter git (not in the repo, not in a commit, not in
  `run/mods` of a tracked path). Product code compiles against a hand-written stub of Meridian's few API types.
- GitHub Actions must still build: nothing the product build needs may live only on this PC.
- Sketch data is for drawing only: nothing a Drifter decides reads it (DESIGN.md section 1).
- No chunk generation far away, no longer loading screen, no server stutter: sketch making runs on `WorldPlan`'s
  low-priority pool and the loading screen never waits for it; painting happens only on the LOD mods' own threads, for
  the columns they ask about.
- Saved data versioned (`SketchVersion`); tunable numbers as named constants.
- No Loom or Gradle bump. No code tests (project rule): `./gradlew build`, headless smoke (`tools/smoke.py`), dev-client
  runs with screenshots, and debug commands that print checkable numbers.
- Never `gradlew build` in a checkout whose dev client or server is running; never replace jars in DRIFTER TEST while
  the game runs (`tasklist` first). Other sessions share the folder: commit only this work's files.
- Version: the next free `0.23.<n>` when it ships (check `gradle.properties`, the installed jar in DRIFTER TEST and every
  recent side branch right before installing; memory note "side branch installs").

## Review Focus

1. An LOD mod missing, older or newer than expected (DH 3.3.3, Meridian 0.3.0, SeedGen 0.9.1): no crash, one log line,
   that hookup off, the game otherwise unchanged. Checked in Task 8 step 4.
2. A world with no plan, the plan setting off, or a plan saved before this existed (no `Sketches` tag): nothing drawn
   for the first two; for the third, sketches made in the background at load and then drawn. Task 2 step 5.
3. A world closed (or a LAN guest leaving) while sketches are being made or while LOD threads are reading them, then
   another world opened: nothing of the old world drawn in the new one, no exception from an LOD thread. Single player
   runs server and client in one JVM, so their two stores must not share state. Task 5 step 4.
4. A sketch on awkward land: a place by water, on a steep hill, at the edge of the surveyed land. No house box in
   water, none floating above or buried in the far land, streets stop at water too wide to bridge. Task 2 step 4.
5. Built state across a restart and across history: a place made, a stretch built, a town that fell to a ruin later.
   The host never draws a sketch over a real town or stretch; the state survives save and load. Task 4 step 4.
6. A LAN guest joining while the host's world is still being built, with thousands of boxes to send: packets split
   under the size limit, sent only to a client that asked, applied in order. Task 5 step 4.

### Task 1: The street laying reads its land through one interface

**Files:** Create `TownLand.java`, `TownStreets.java`; modify `TownBuilder.java` (`Job.layout` and what it calls up to
`lots`: `survey`, `pickShape`, `mainHeadings`, `flattestAxis`, `laying`, `main`, `lay`, `choose`, `ring`,

**Interfaces (produces):**
- `interface TownLand { int ground(int x, int z); boolean wet(int x, int z); boolean usable(int x, int z); }`

- `TownLand.of(ServerLevel)`: today's `TownBuilder.ground` / `wet` / `loadedAt` / `built`.
- `final class TownStreets`: `TownStreets(TownLand land, RandomSource random, int cx, int cz, boolean city, boolean ruin,

### Task 2: The sketch of each place

**Files:** Create `Sketch.java`, `Sketches.java`; modify `WorldPlan.java` (`apply`: start making; `save`/`load`; the
`Plan`'s `realLand` and biome lookups reachable as a `TownLand` and a style), `DrifterCivilizations.java` (commands).

**Interfaces (produces):**
- `record Sketch(UUID place, int x, int z, int y0, String style, String shape, double[] headings, long seed, int reach,
  int[] plaza, List<int[]> streets, List<Box> boxes, List<int[]> fields, List<int[]> lamps)`: `plaza` and each field
  `{x0, z0, x1, z1}`; each street a flat `{x, z, x, z, ...}` line, a point every 4 blocks, its first int the width;
  each lamp `{x, y, z}`.
- `record Sketch.Box(int x0, int z0, int x1, int z1, int base, int wall, int roof, byte wallBlock, byte roofBlock,
  boolean ridgeAlongX, boolean lit)`; `wallBlock` / `roofBlock` index `Sketch.PALETTE` (a fixed list of block ids:
  planks of the six woods, cobblestone, mossy cobblestone, stone bricks, sandstone, smooth sandstone, cut sandstone,
  their stairs' full-block stand-ins for roofs). A ruin's boxes: `roof = 0`, `wall` 1 to 3.
- `CompoundTag Sketch.save()`, `static Sketch Sketch.load(CompoundTag)`; `void write(FriendlyByteBuf)`,
  `static Sketch read(FriendlyByteBuf)`.
- `Sketches.start(MinecraftServer, TownLand predicted, Function<int[], String> styleAt)`: on `WorldPlan`'s pool, nearest
  to spawn first, one place at a time; stops when the world's generation counter moves on.
- `Sketches.of(UUID place)` (null until made), `Sketches.all()`, `Sketches.ready()`; `Sketches.save(CompoundTag plan)`,
  `Sketches.load(CompoundTag plan)` under `"Sketches"` with `"SketchVersion" = 1`; an unknown version or a missing tag
  means: make them again.
- Constants: `SKETCH_GRID = 8` (predicted heights asked this far apart, the rest by bilinear blend), `HOUSE_MIN = 7`,
  `HOUSE_MAX = 13`, `SETBACK = 3`, `HOUSE_GAP = 3`, `WALL = 4` (a city's `6`), `ROOF = 3`, `LAMP_EVERY = 14` (the real
  builder has no spacing number: it puts lamp posts where its light pass finds dark ground, `TownBuilder` near line
  3700; count the posts along a street of a made town and set this to match), `LIT_SHARE = 0.4` (houses with lit windows),
  `MOST_MS_PER_PLACE = 250` (logged when passed).

**How a sketch is made:** style from the biome at its middle (the same tags as `TownBuilder.Style.at`); `TownStreets`
on the predicted land with `Sketches.seedOf`, the place's gates, its kind's size; house boxes walked along both sides of
every street as the real lots are (setback, gap, sizes from the constants, wall and roof blocks from the style's woods
by the seeded random), none where the predicted ground is water or steps more than 3 across the box; fields as two to
four rectangles off the first roads; lamps at the plaza's corners and along the streets; a city uses the city reach and
arm; a hamlet, a main street; a ruin, a third of the houses.

**Debug commands:** `/drifterciv sketch info` (nearest place: shape, streets, boxes, lamps, milliseconds),
`/drifterciv sketch check` (every sketch: boxes in water, boxes overlapping a street or each other, places with no
streets; prints counts, 0 expected), `/drifterciv sketch stamp` (puts the nearest sketch into the world as real blocks,
for a look and for screenshots; loaded chunks only).

### Task 4: The painter

**Files:** Create `FarPaint.java`; modify `Highways.java` (a stretch built: tell the painter), `WorldPlan.java` (`made`:
tell the painter), `RoadLamps.java` (`static List<double[]> spots(List<double[]> points, double[] s, long salt)`: the
lamp spots `light` would try, `{x, z, side}`, with no level: same `EVERY`, `END_GAP`, sides and salt).

**Interfaces (produces):**
- `final class FarPaint` with two instances, `FarPaint.SERVER` and `FarPaint.CLIENT` (single player has both in one
  JVM; they never share state). Each holds one immutable snapshot behind a `volatile` field; readers on any thread.
- `void set(Collection<Sketch> sketches, List<Road> roads)`, `void built(UUID place)`, `void built(int road, int piece)`,
  `void clear()`; `record Road(int index, List<double[]> line, boolean[] bridge, int[] deckY, boolean[] built)`
  (`line` from `Highways.smooth`; `bridge` from a point's third value; pieces of `Highways.PIECE` points).
- `boolean touches(int chunkX, int chunkZ)`: anything unbuilt in this chunk (a lookup in a grid of 64-block cells).
- `@Nullable Column column(int x, int z, int ownSurfaceY)`: null where nothing's drawn.
  `record Column(@Nullable BlockState surface, int surfaceY, List<Span> spans, int light)`; `record Span(int bottom,
  int top, BlockState block, int light)`. `surface`: the block the LOD's own surface becomes (street, plaza, road mud,
  field); `surfaceY`: `ownSurfaceY`, or a house's base; `spans` bottom to top above it (wall, roof; a bridge deck over
  water; a lamp's lit block); `light`: block light 0 to 15 on the surface, 15 at a lamp falling by one a block to 0, 10
  beside a lit house.
- Constants: `ROAD_WIDTH = 3` (5 within 40 blocks of a place's reach), `LAMP_UP = 4`, `LAMP_LIGHT = 15`,
  `WINDOW_LIGHT = 10`, `CELL = 64`.

**Behaviour:** road surface blocks from `WildRoad.mix(x, z, off, salt)`; a deck of the style's planks at the plan's
bridge height; a roof's height at a column is `min(distance to the two long edges, roof)` so it reads as pitched; a
place's own streets use its style's path block. Built places and built pieces are skipped by `column` and `touches`.

**Debug command:** `/drifterciv sketch paint <x> <z>` prints that column's answer from `FarPaint.SERVER`;
`/drifterciv sketch painted` prints counts (cells, sketches drawn, road pieces drawn, built skipped).

### Task 5: Sketches to the client

**Files:** Create `FarSync.java`, `src/civClient/.../client/FarView.java`; modify `DrifterCivilizations.java`,
`DrifterCivilizationsClient.java` (register).

**Interfaces (produces):**
- C2S `drifter_civ:far_want` (`record Want()`): sent by a client on join when an LOD hookup is on.
- S2C `drifter_civ:far_part` (`record Part(int index, int of, byte[] bytes)`): the sketches and road lines, written with
  `Sketch.write` and deflated, cut into parts of at most 500,000 bytes.
- S2C `drifter_civ:far_built` (`record Built(Optional<UUID> place, int road, int piece)`).
- Server: on `Want`, sends the parts once (again when `Sketches.ready` turns true later), and every later `Built` to
  that player; forgets the player on disconnect. Client (`FarView`): gathers parts in order, fills `FarPaint.CLIENT`,
  applies `Built`; `FarPaint.CLIENT.clear()` on disconnect.
- `FarView.hookups()`: which of `FarDh`, `FarMeridian` are on (empty: `Want` is never sent).

- `DhApiEventRegister.on(DhApiLevelLoadEvent.class, ...)`: for a level whose wrapped object is the overworld
  `ServerLevel` of a planned world, `DhApi.worldGenOverrides.registerWorldGeneratorOverride(level, new Wrap(level))`,
  priority 50.

  highest other override in `WorldGeneratorInjector.INSTANCE`'s per-level map (priorities 49 down to 0; SeedGen's is
  10), else a new `com.seibel.distanthorizons.core.generation.DhWorldGenerator` for

  `try`: on failure, one log line, no override registered (DH carries on as without us).

  the section touches a place whose sketch isn't made yet, the call is chained on that sketch's future (a
  `CompletableFuture` per place in `Sketches`), with a 60 second limit after which it goes ahead unpainted. Otherwise
  delegate with our own result consumer: paint, then pass on.

  light 15 above the highest span, 0 under it. Block wrappers from `DhApi.Delayed.wrapperFactory`, cached per
